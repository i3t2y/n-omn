## 1. 归因修订史(四候选排除链)

事件原象: 2026-07-21T03:16Z 复测 ④ priority 多发全崩, 全 9 NIM key glm-5.2/pro 双模型均返回 `403 "Authorization failed"`, 换 IP 测两不同 key 仍 403. pm.py 手动实测 9/9 全 403. 25 key 历史未现此状.

四候选逐排除:

| 候选 | 定性 | 证据 |
|---|---|---|
| (a) 额度耗尽 | ❌ 证伪/降级 | `Authorization failed` 为鉴权拒绝非额度耗尽; 额度耗尽应返回 429 非 403. pm.py 9/9 403 |
| (b) IP 封禁 | ❌ 排除 | 用户换 IP 测两不同 key 仍 403, IP 维度被证伪 |
| (c) 200 RPM 提额通道 / 提额可解 | ❌ 作废(单列保留) | 403 非 RPM 限流签名, 提额不解鉴权失败. 200 RPM 通道仅作"解封分支验证"用, 非解 403 本身 |
| (d) 账户级风控穿透重启 | ✅ 主因(外) | `audit/2026-07-20-r3plus-group1v2-429-rootcause` 两轮 03:16 全池 403/404 归因: 8 账户中 2 个全模型 403 ≥2h 封禁倾向 + 6 个 pro 404, 穿透重启, 熔断到期后仍全崩 |

修订史:
1. 初判: 单 key 故障 → 全池 403/404 集体, 推翻为账户级
2. 副因(内)引入: 健康检查流于形式(疑点4) → 死模型导流诱罚. init L247 `check_nim_model_health` 仅 `GET /v1/models` 数目录项, 无真推理 ping
3. 最终定性: **主因外(账户级风控) + 次因内(健康检查流于形式致死模型导流诱罚)**
