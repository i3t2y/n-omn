### **四、文档更新指南**

文档从 v3.4.x 到 v4.1.1 跨越了多个大版本，需要全量重写。以下是文档应覆盖的完整内容框架：

#### **4.1 架构概述**

文档应描述当前的三段式架构：

- **OmniRoute 3.8.43**（基础镜像，Dockerfile 钉死 tag+digest）：提供模型路由、combo 轮询、熔断器、请求队列等核心能力
- **gate.js**（Express 反向代理网关）：监听 7860 端口，`INTERNAL_PSK` 鉴权，将 `/v1` 请求的 Bearer 替换为内部 `OMNIROUTE_API_KEY` 后转发至 OmniRoute 20128 端口
- **Litestream v0.5.9**（SQLite WAL 复制）：启动前从 R2 恢复数据库，运行时每 10s 同步 WAL，每小时快照，24h 保留，`auto-recover` 适配 HF 免费层 OOM 自愈

v3.4.x 文档中可能缺失的架构变更：

- gate.js 的 `INTERNAL_PSK` 鉴权机制（v3.4.x 时期可能不存在）
- `OMNIROUTE_API_KEY` env-bypass 模式（跳过 `.or-api-key` 文件等待）
- Litestream 的 `auto-recover` 特性（v0.5.7+ 新增）
- Dockerfile 的 `OMNIROUTE_USE_TURBOPACK=0` 和 `OMNIROUTE_MAX_PENDING_MIGRATIONS=0` 跨版本防御阀

#### **4.2 三大技术坑位与修正**

这是文档中最关键的部分，v3.4.x 文档完全未覆盖：

**坑位 1 — proxy_registry 全局兜底（Issue #3332）。** 当 `proxy_registry` 表存在任何记录时，`getProxyCandidates()` 会将其作为全局兜底代理应用到所有 provider，且绕过 `proxy_enabled` 字段。表现为所有请求被路由到 `127.0.0.1:20129`（OmniRoute 的 API_PORT，非代理服务），导致 `ECONNREFUSED`。根治方案：`purge_proxy_db` 函数在登录后、注册 key 后、初始化末尾三次清理 registry + assignments + `proxy_enabled=0`，配合环境层 `ONEPROXY_ENABLED=false` + `ENABLE_SOCKS5_PROXY=false`。`NO_PROXY` 环境变量对此无效——代理来自数据库而非环境变量。

**坑位 2 — combo models 格式。** OmniRoute 的 `/api/combos` 接口要求 `models` 字段为对象数组 `[{"model":"x"}]`，而非字符串数组 `["x"]`。错误格式返回 HTTP 400。修正：`models_to_json()` 函数使用 `jq -R '{model: .}' | jq -s -c .` 生成正确格式。

**坑位 3 — 裸 ID 路由歧义。** OmniRoute 内置多个 provider 的模型前缀映射表（`kc` 拦截 `moonshotai/`、`qwen` 拦截 `qwen/`、`cline` 拦截 `nvidia/`、`01-ai` 拦截 `01-ai/`）。combo 内使用裸 ID 轮询时，OmniRoute 路由层发现裸名匹配多个 provider，返回 400 "Ambiguous model"。根治方案：`models_to_json()` 添加 `sed 's/^/nvidia\//'` 前缀，强制路由到用户注册的 `nvidia` provider。

#### **4.3 模型分档与权限层级**

文档需明确三档模型的权限差异：

- **TIER_FAST / TIER_STABLE**（共 11 个）：NVIDIA 账号默认开放，`/v1/chat/completions` 调用返回 200。`NIM_PROFILE=balanced` 时入池。
- **TIER_RESTRICTED**（5 个）：NVIDIA 目录中可见（`/v1/models` 返回），但 `/v1/chat/completions` 调用返回 404（Function not found for account）。需在 NVIDIA 开发者控制台申请 Public API Endpoints 权限。`NIM_PROFILE=full` 时入池，`balanced` 时排除。
- **`check_nim_model_health` 的局限性**：探活仅验证目录存在性（`/v1/models`），不验证调用权限（`/v1/chat/completions`）。目录可见 ≠ 可调用。

文档需列出全部 17 个变量（16 个现有 + 1 个新增 `NIM_PROFILE`），区分 Public Variable 和 Secret，标注默认值和消费位置。v3.4.x 文档中可能缺失的变量：

#### **4.5 运维指令**

- **一键排查**：HF Settings 设置 `NIM_MODE=DEBUG`，Factory Reboot，查看 `/data/omni-data/log/init_*.log`
- **版本确认**：日志中 `OmniRoute base image version: 3.8.43 (expected 3.8.43)` 确认镜像未漂移
