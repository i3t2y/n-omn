## 一、P1 级问题（修复前不放行 Step C）

### **P1-1：gate.js 不再识别 `X-Internal-PSK` 头——回归 bug，客户端按文档配置将全部 401**

第 154-158 行的 PSK 校验只读了 `authorization` 头：

```javascript
const auth = req.headers['authorization'] || '';
const bearer = auth.startsWith('Bearer ') ? auth.slice('Bearer '.length).trim() : '';
if (!PSK || !safeCompare(bearer, PSK)) {
```

v2.0 原版是 `req.headers['x-internal-psk'] || req.headers['authorization']` 双通道。现在 `x-internal-psk` 完全被忽略——而方案文档、README、运维手册全部指示客户端使用 `X-Internal-PSK` 头接入（第 5 章第 6 步原文："头 `X-Internal-PSK: <INTERNAL_PSK>`"）。更讽刺的是后面 `delete headers['x-internal-psk']` 还保留着，说明合并时删除通道检查是无意的。**修复**（恢复双通道，Bearer 优先）：

```javascript
const xPsk = req.headers['x-internal-psk'] || '';
const auth = req.headers['authorization'] || '';
const bearer = auth.startsWith('Bearer ') ? auth.slice('Bearer '.length).trim() : xPsk;
if (!PSK || !safeCompare(bearer, PSK)) {
```

### **P1-2：adminMode 删除 Authorization 头后不注入上游管理凭据——后台看板对上游全部 401/403，功能形同虚设**

第 179-182 行：gate 验证 Basic Auth 后 `delete headers['authorization']`（防 GATE_ADMIN_TOKEN 泄露给上游——这个动机是对的），但**没有注入任何替代凭据**。结合查证 2：上游管理路由要求 dashboard session 或 manage-scoped Bearer，而浏览器两样都拿不到——`/api/auth/login` 不在白名单（404，拿不到 auth_token cookie），Authorization 头又被删（传不了 manage key）。结果：开启后台后，白名单内每个 API 上游都返回 401/403。这个 fail-safe 设计把"后台"做成了只能加载静态页面的空壳。

**修复方案**（两步，保持防泄露语义）：init 脚本利用容器内 Cookie 鉴权通过 `POST /api/keys` 创建一把 manage-scoped key 写入 `/data/.manage_key`（/data 不随镜像分发，仅容器内可读）；gate 启动时读取该文件，adminMode 校验通过后注入：

```javascript
if (adminMode) {
  delete headers['authorization'];                 // 删掉 Basic 凭据（保留防泄露语义）
  if (MANAGE_KEY) headers['authorization'] = `Bearer ${MANAGE_KEY}`;  // 注入管理 key
}
```

若 `/data/.manage_key` 不存在则 adminMode 照常工作但上游继续 401——日志中 WARN 一次即可。同时 Secrets 清单和运维手册需补记这一机制。
